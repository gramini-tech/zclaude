Several accounts. One session across all of them.

Claude Code keeps one login per machine, so signing in to a second account signs you out of the first, VS Code included. Whichever account you start a session on is the one you finish it on, however full it gets. And nothing tells you which of your accounts still has room. zclaude answers all three by making the account a finer choice: one per terminal, with a profile that carries its own credentials and config directory; one per request, with a local router that sends each class of model wherever a route table says, across your accounts and across providers, inside a single session; and one per machine when you want it, with a switch that moves the login plain claude and the VS Code extension share. Every plan's five-hour window, week and per-model limits are on screen while you choose. A company seat and a personal subscription on one email count as two accounts, and a Z.ai GLM Coding Plan is one more provider a route can name.

And one session across every account you have

A profile picks an account when the session starts. The router picks one for every request. It is a small proxy on 127.0.0.1 that Claude Code points at for the length of a session, and each class of model (opus, sonnet, haiku, fable) goes wherever a route table says. The main turn rotates across your Anthropic accounts as their windows fill; the subagent turns are answered by a GLM model. One Claude Code session, nothing changed inside it, and nothing to restart when an account runs out. 

$ zclaude router config init
✓ Wrote ~/.zclaude/router.json.

$ zclaude router route sonnet glm any
✓ sonnet now goes to glm, then any.

$ zclaude router on
✓ Routing is on for sessions started by zclaude.
· Plain claude, other terminals and the editor extension are untouched.

$ zclaude router status

  opus     work then any
  sonnet   glm then any
  haiku    glm-fast  (pinned)
$ zclaude router log
19:32:45  200  sonnet  any→hoomanely   3454ms  2in/3out +24124c
19:32:45  200  sonnet  any→gramini     1380ms  2in/5out
19:31:02  200  haiku   glm-fast→zai     412ms  2in/9out
19:30:51  200  opus    work→work      8129ms  4in/612out +91002c

The left of each arrow is the route table entry, the right is the account or provider that actually answered. Two sessions running at the same moment land on different accounts because the ranking looks at what is left on each. No model version appears in the route table: a Z.ai target names latest or latest:fast, resolved against what the provider publishes at the moment the request is sent.

A quota 429 moves the request to the next account in the chain. A burst 429 does not, and that distinction is most of the value: rotating to dodge a two-second pace throws away a warm prompt cache, which on an agentic turn is most of the input tokens. When nothing in a class’s chain can take a request it holds quietly for up to four minutes and then returns a real 429 with a retry-after, because a keep-alive would have to commit a 200 first and after that there is no 429 left to send.

It changes nothing outside the session it serves. It never calls switch, never writes your settings, and never refreshes a token something else might be holding. zclaude router open gives you a page on loopback to edit the table, see what each selector resolves to right now, and watch the log arrive: metadata only, no prompts and no responses, with no setting that turns that on.

Several accounts, side by side

A profile is a name, a provider (an Anthropic account or a Z.ai coding plan), its own Claude Code config directory, and a choice about what it borrows from your main setup. Credentials are keyed by that directory, which is what keeps the accounts apart. A profile holds a billing context as much as a login: a company seat and a personal subscription on one email address are metered separately, so they get a profile each, and profile list shows the organization beside the address to tell them apart.

zclaude profile add work Create one. The wizard asks for the provider, sharing, MCP servers, trust and sign-in.
zclaude work Launch Claude Code on that account, for this terminal only.
zclaude profile shell work A subshell where plain claude is that account.
zclaude profile list Every profile with its signed-in identity and what it shares.
zclaude profile show work Its directory, credential item, identity and shared items.
zclaude profile login work Sign in, or sign in again. --sso and --console pass straight through.
zclaude profile logout work Sign that profile out. The others are untouched.
zclaude profile remove work Delete the profile, its login and its directory.
zclaude profile doctor Check every profile, this shell, and any machine-wide policy that applies.

What a profile shares

By default a new profile borrows your settings and your history, so it works straight away. Shared settings are your agents, commands, skills, rules, output styles, workflows, themes and CLAUDE.md, plus a filtered copy of settings.json that drops anything which would hand the profile another account's credentials or models. Shared history is projects/ and history.jsonl, so /resume spans profiles. Pick --share config, --share history or --share none instead, and change your mind later.

Credentials, .claude.json, installed plugins, caches and telemetry are never shared. Nor is anything about your identity copied into a new profile: it starts signed out and earns its own login.

How much of each plan is left

Picking an account is usually a question about quota, so every surface answers it: the launch menu while you choose, profile list --usage spelled out, and the editor’s status bar. A row carries the rolling five-hour window, the week, and each model window metered separately — Fable has its own ceiling — plus any pay-as-you-go credit. 

$ zclaude profile list --usage
work      anthropic  you@company.com · Acme Inc  shares config + history
          5 hours       80%  resets in 2h 30m (07:50 pm)
          week          21%  resets in 6d 7h (Thu, 24 Sept, 12:30 am)
          Fable week    33%  resets in 6d 7h (Thu, 24 Sept, 12:30 am)
          credits $37.66 left

Reset times arrive in UTC and are shown in your own zone and clock format, because nobody plans their afternoon in UTC. Both forms are there on purpose: “in 2h 30m” answers how long, “07:50 pm” answers when. A window under half full carries no clock, since nobody is waiting for it.

A lookup costs a network call per account, so it never happens on the launch path and never without a terminal. Answers are cached for a minute and a Retry-After is obeyed across every surface, so the CLI and the editor cannot saturate the endpoint between them. A login that has expired says so, and says what to run — or, in the menu, offers s to sign it in where you are looking at it.

Switching the login everything else uses

Profiles cover the terminals you start with zclaude. Plain claude, the Claude Code extension in your editor, and anything else that shells out to Claude Code all use the machine’s one global login. zclaude switch moves that login to a profile’s account, in place, and leaves your projects, history, sessions and MCP logins exactly where they are.

zclaude switch work The global login is now that profile’s account.
zclaude switch --status Who holds it, since when, and what can be restored.
zclaude switch --restore Put the previous one back.
zclaude switch work --dry-run Say what would change, change nothing.
zclaude vscode install Put the zc item in the status bar of every editor found here.
zclaude sessions What is running, on which account, and whether it is busy or idle.
zclaude renew status Is the background token renewal scheduled, and what did it do.

Two things move and nothing else: the credential in the Keychain item Claude Code reads, and the oauthAccount block of ~/.claude.json. Both are backed up and read back before anything is overwritten, the login being replaced is captured back into the profile it belongs to so a token Claude Code rotated is not stranded, and Claude Code’s own refresh locks are held throughout so a switch cannot land in the middle of one.

The status bar item

A small extension puts zc in the VS Code status bar with the signed-in account beside it. One click lists every profile with its 5-hour, weekly and per-model usage, so you can pick the account that has quota left for the job; a window near its ceiling also carries the time it comes back, in your own time zone. The same list adds a profile, removes one, restores the previous login and re-fetches usage. It works in VS Code, Insiders, Cursor, Windsurf and VSCodium, and it holds no credential logic of its own: it asks zclaude for JSON and renders the answer.

Who is already using that account

Two terminals on one account share its five-hour window, so the menu marks a profile that is already busy before you pick it, and zclaude sessions lists what is running and where. A session counts as live only when its process id exists and that process still started when the record says it did — without the second check a recycled id would leave an account looking busy for ever. Busy and merely open are different questions: Claude Code appends to its transcript as a conversation goes, so a session quiet for five minutes is reported as idle rather than active. It never blocks a launch; it is there so the decision is yours.

Logins that do not go stale

An account you open twice a term expires quietly between uses. zclaude renew install schedules a job — a LaunchAgent on macOS, a systemd user timer or a crontab line on Linux — that refreshes only what is within two hours of lapsing, one profile at a time, and stops at the first token the server rejects rather than hammering it on a timer. Removing the last Anthropic profile removes the schedule, and so does any uninstall.

Rotating by usage

Long work ends the same way every time: one account hits a wall while the others still have room. zclaude --auto <profile> starts a session that may be moved between accounts as they fill up, and zclaude auto status says which one it would use and why. Rotation only ever happens for a session that asked for it — an open editor window is not consent to move the login everything else on the machine shares.

This moves the machine’s login, which is why it waits, settles and keeps a budget. The router answers the same complaint at a different scope: it picks per request and changes nothing outside the one session, so it needs none of that caution. Use the router for the session you are working in, and auto for everything on the machine that is not routed. 

$ zclaude auto run --dry-run
  wait — gramini is at 50% of its weekly; something is mid-answer
  …ninety seconds of that, because the session never stopped writing
  switched — gramini → max
  stay — 3% of its weekly
  stay — 4% of its Fable

Four things in that trace are the whole design. It waited rather than landing mid-answer, and gave up waiting after ninety seconds because a session that never goes quiet is one long turn. It settled once it arrived instead of hopping back. And the class it reasons about changed from Opus to Fable partway through, because that is what the transcripts said was in use — work never drops to a weaker model to keep going, so the ceiling that binds followed it.

Accounts are compared in units of work rather than percentages, because 3% used on a Max 20x seat is nine times the room left in 55% used on a 5x seat. The plan size comes off the credential, so there is nothing to configure. A login that failed is never read as an empty account: the cache keeps serving its last good numbers when a lookup fails, which is right for a display and a trap for a scheduler.

zclaude auto run --dry-run runs the entire loop and makes none of the decisions, which is how a thing that moves your login while you are not watching earns the right to do it. Everything it owns says when it is dead rather than relying on cleanup: a watcher killed outright, or a machine that loses power, leaves a lock that reads as stale to whoever looks next.

What it does for you

  • An account per request

    The router sends each class of model wherever the route table says, and moves on when an account’s window is spent. One session, no restart, no switching.

  • Two providers in one session

    Sonnet-class work to a GLM model while Opus work rotates across your Anthropic accounts. The response body is never rewritten, so each turn is attributed to the provider that answered it.

  • No model version written down

    A route names latest or latest:fast, resolved against what the provider publishes when the request is sent. A route you wrote last year still means the current model.

  • Accounts side by side

    Each profile gets its own config directory, so Claude Code stores its credentials under a separate Keychain item. No switching, no signing out.

  • What is left, before you pick

    The five-hour window, the week and every model metered separately, with the time each comes back in your own zone. Shown while you choose, not after the limit arrives.

  • Numbers that improve as you work

    Every routed response carries that account’s own quota headers, so the usage you see is refreshed by traffic you were sending anyway rather than by polling.

  • One email, two plans

    A company seat and a personal subscription bill and meter separately. Each gets a profile, and the list shows the organization so you can see which is which.

  • Scoped to the terminal

    A profile lives in the environment of the one claude process it starts. Your default login and the VS Code extension carry on unchanged, until you ask for a switch.

  • Usable from the first run

    A new profile borrows your settings, skills and commands by default, so it behaves like your normal setup without copying your secrets.

  • Z.ai coding plans too

    Browser sign-in issues a coding-plan key, stored in the Keychain, with the GLM models you pick for the main agent, subagents and helpers.

  • Nothing written to ~/.claude, unless you ask

    zclaude reads your Claude Code files. The one exception is the switch you name: it moves the credential and one key of ~/.claude.json, backs both up, and can put them back.

  • A switch, and a button for it

    zclaude switch work moves the global login that plain claude uses. The VS Code status bar item does the same thing in one click, with each plan's usage on the list.

  • Logins kept alive

    A scheduled job refreshes a profile's token before it lapses, so an account you open twice a term is still signed in when you come back to it.

  • Honest about the edges

    profile doctor reports a shell that pins a config directory, a share that detached, and any machine-wide policy no profile can escape.

  • Run logs

    Each run writes a redacted JSON log. zclaude log shows the last one when something needs a closer look.

  • Updates itself

    Every push is a new version. A daily check tells you when one is out, and zclaude self-update installs it.

FAQ

What is zclaude?

A launcher for Claude Code. It starts claude with the profile you pick: your usual login, a second or third account, or a Z.ai GLM Coding Plan. Everything it configures is passed to that one process, so your normal setup stays where it is.

How can several accounts run at once?

Claude Code reads its configuration from CLAUDE_CONFIG_DIR and keys its stored credentials by that directory. zclaude gives each profile its own directory and sets that variable for the one process it starts, so each terminal has its own login. It never sets the variable for your default profile, because Claude Code treats the presence of the variable, and not its value, as a different account.

What does the router actually do?

It is a proxy on 127.0.0.1 that Claude Code points at for the length of a session. Each request already says which class of model it wants, so the router reads that, looks it up in a route table, and sends it to the account or provider named there. Only generation is routed; usage lookups, token counting and everything else pass through untouched. The request and the response stay in Anthropic Messages shape, so Claude Code never learns anything happened.

How is routing different from zclaude switch?

Scope. A switch moves one login for the whole machine, so it is deliberate and slow and careful. The router changes nothing outside the session it serves, so two routed sessions can be on two different accounts in the same millisecond while a third terminal running plain claude knows about neither. They answer different questions and you can use both: keep the switch for the login your editor shares, and the router for the session you are working in.

What happens when an account runs out mid-session?

The next request goes to the next target in that class’s chain, and the spent account sits out until its window resets. Nothing restarts. There are two kinds of 429 and the router tells them apart: a quota 429 moves on, and a burst 429 waits out its retry-after on the same account, because rotating to dodge a two-second pause throws away a warm prompt cache worth most of an agentic turn’s input tokens. If nothing in the chain can take it, the request holds quietly for up to four minutes and then gets a real 429 with a retry-after that Claude Code’s own retry handles.

Do I have to name a model version in the route table?

No, and the design goes out of its way to stop you. A Z.ai target names a selector — latest, latest:fast, or an exact id if you really mean one — resolved against what the provider publishes at the moment the request is sent. Routes key on the class of model, so a model released tomorrow routes correctly with no edit. An exact id the provider has retired moves forward to the newest with a warning rather than failing an hour later with a 404. A test asserts that no concrete model id appears anywhere in the router’s source or in its local page.

Does the router log my prompts?

No. It records the class, the target, the account that answered, the model id, the status, the duration and the token counts. No prompts and no responses, not behind a flag, and there is no setting that turns it on. It lives in memory, capped, and goes when the process does. The page that shows it binds to loopback only, checks the Host header on every request, and the proxied paths ignore cookies entirely, so a page in your browser cannot make the browser spend your quota.

Can the router route everything on the machine, not just zclaude sessions?

Not yet, and the reason is stated rather than hidden. Machine-wide interception means writing ANTHROPIC_BASE_URL into Claude Code’s own user settings, which makes a local process a dependency of every Claude Code on the machine — and a router that is down does not read as down, it reads as a connection refused inside somebody’s editor. That mode is designed and not built. zclaude router status says session and will keep saying it until it is.

Does signing in to a profile sign me out of VS Code?

No. The extension uses the default login, which adding or signing in to a profile never touches. That is checked end to end: create a profile, sign in, and plain claude in a fresh terminal still reports the original account. The one thing that does move it is zclaude switch, which you ask for by name and can undo with zclaude switch --restore.

What does a switch do to a session that is already running?

Nothing immediately. Claude Code keeps the credential it read at startup, and on macOS that cache lasts about half a minute, so a running session moves to the new account shortly rather than mid-answer. A switch also takes Claude Code’s own refresh locks first, so it cannot land inside a token refresh.

Can I switch a Z.ai profile globally?

No, and it is not a gap in the implementation. A GLM plan is an endpoint and a key, which reach Claude Code through the environment rather than through its credential store, so the only way to make it global would be to write your settings.json. zclaude will not do that. Run zclaude <profile> in a terminal instead.

Can it tell me an account is already in use?

On this machine, yes. Every session zclaude starts is recorded and verified against the process that claims to be it, so the menu can mark a busy profile and zclaude sessions can list them with how long each has been quiet. Sessions started outside zclaude are counted too: they cannot have a config directory of their own, so they are all on the global login and are attributed to whichever profile holds it. What it cannot see is another machine — your laptop and your desktop spend the same account and neither knows about the other.

Can I see when my limit resets?

Yes. The menu, zclaude profile list --usage and the status bar item all show the reset time for any window at half its limit or more — both as a countdown and as a wall-clock time in your own zone, converted from the UTC the API answers in. A window at 4% is left bare, because a clock on every row buries the numbers. Pay-as-you-go credit shows up on the same line when the account has it switched on.

How do I get the status bar item?

The installer offers it when it finds an editor, or run zclaude vscode install yourself; it goes into VS Code, Insiders, Cursor, Windsurf and VSCodium. Reload the window afterwards. It is not on the Marketplace: the packaged .vsix ships with zclaude and is installed from disk.

Work and personal on one machine: what stays separate?

Credentials, the signed-in identity, transcripts and project memory, MCP servers, tool permissions, folder trust and installed plugins. Shared, only if you ask for it, are your settings and your history. Machine-wide policy from an employer's MDM applies to every profile, and the device key file Claude Code writes in your home directory is shared too. zclaude profile doctor tells you when either applies.

I use one email for a company seat and a personal plan. One profile or two?

Two. They are separate organizations with separate billing and separate usage, and Claude Code stores them as different logins, so a profile each is what keeps their sessions and quotas apart. Both rows show the same address in zclaude profile list, followed by the organization: the company name for the seat, and personal for the subscription billed to you.

Can I share my skills and commands with a new profile?

Yes, that is the default. Agents, commands, skills, rules, output styles, workflows, themes and CLAUDE.md are linked, and your settings.json is copied through a filter that drops authentication and, for a Z.ai profile, the model keys that would fight your GLM choices. Edits to the originals follow. --share none gives you a clean profile instead.

What happens to /resume across profiles?

With shared history, projects/ and history.jsonl are shared, so /resume and claude --continue can reach a session started under a different profile. Handy for one person with several accounts, and the wrong default if the profiles are for different clients. --share config keeps the settings and separates the transcripts.

Is it made by Anthropic or Z.ai?

No. zclaude is an independent open-source project under the MIT license. It uses the environment variables Claude Code documents and the same browser sign-in that Z.ai's ZCode desktop app uses.

What do I need?

A Mac or Linux machine and Claude Code. The curl installer adds Claude Code if it is missing, and Node.js only if yours is missing or older than 20.17. A Z.ai profile needs a GLM Coding Plan subscription. On Windows, install with npm; the Z.ai sign-in asks you to paste the redirect URL.

Does it change my Claude Code settings?

zclaude never writes to ~/.claude/settings.json or your project’s .claude folder. It reads them, to seed a profile you asked for and to spot an env block that would override your session. The single exception is the switch you ask for by name, which replaces the stored credential and the oauthAccount block of ~/.claude.json — both backed up first, both restorable, and the only key of that file that moves. Claude Code itself writes ~/.claude/.device-keys.json whatever config directory it is given, so that one file appears even for a profile. The test suite hashes the directory before and after a run.

My settings.json already sets ANTHROPIC_* variables. What happens?

Claude Code applies the env block of its settings over the process environment, which would quietly undo the session zclaude set up. So zclaude shows each conflicting variable with both values and asks whether to stop so you can edit the file, or launch anyway. It checks your user settings, the project file, the project-local file and machine-wide policy, and it does not edit any of them for you.

My company enforces a policy. Will a personal profile escape it?

No, and zclaude will not pretend otherwise. Managed settings live outside your home directory and apply to every Claude Code session on the machine. zclaude profile doctor names the file that applies so you know where the rule comes from.

Where is my key, and how do I remove it?

A Z.ai key goes in the macOS Keychain under the service name zclaude, one item per profile, or in a 0600 file on Linux. zclaude logout and zclaude profile logout remove the local copy; the key also exists on your Z.ai account until you revoke it there. Anthropic logins are stored by Claude Code itself, and zclaude only ever asks whether an item exists.

Which Z.ai models can I pick?

Whatever Z.ai's model list returns for your plan, such as glm-5.3, glm-5.3-flash and glm-4.7. The wizard also accepts a custom model id. Models with a 1M context window are passed to Claude Code with the [1m] suffix it expects.

How do I pass claude's own options, like resuming a session?

Put them after the profile name: zclaude work --resume <session-id>, zclaude work -c, zclaude work -p "explain this". The name ends zclaude's own options, so everything after it is claude's, including flags zclaude also defines. Without a profile name, -- does the same job: zclaude -- --resume <session-id>, and zclaude -- --help for claude's help. Session ids belong to a config directory, so they follow the profile; with shared history a session started under one profile can be resumed from another.

What if a profile is named like one of claude's commands?

It cannot be. zclaude mcp list has to reach claude's MCP command, so claude's own command names are reserved and a profile cannot take one. The first word after zclaude is treated as a profile only when a profile by that name exists; anything else is passed straight through, and a name that matches nothing brings up the menu with your arguments intact.

How do I go back to my usual Claude Code?

Pick "Claude Code" in the menu, run zclaude --profile claude, or just run claude as before. Nothing about your usual setup was changed.

Will the installer replace my Node.js?

No. If node is 20.17 or newer it is used as is. If it is missing or older, the installer downloads an official, checksum-verified build into ~/.zclaude/node for zclaude alone and leaves your system Node and your PATH for Node untouched.

How do I update or uninstall?

zclaude self-update updates it the same way it was installed. zclaude self-uninstall removes it: the files, the command, the profiles, settings and logs in ~/.zclaude, your stored Z.ai keys and the Claude Code login each profile earned. Add --keep-config to keep ~/.zclaude. The installer can do the same directly with curl -fsSL https://gramini-tech.github.io/zclaude/install | bash -s -- --uninstall. Installing and removing it repeatedly is fine.

Something went wrong. What should I look at?

Run zclaude log. Every run records the profile, config files, key source and validation, each HTTP call with its status and timing, and how Claude Code was started and exited. Keys are redacted, so zclaude log --json is safe to attach to an issue. For anything profile-shaped, start with zclaude profile doctor.
